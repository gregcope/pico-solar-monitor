# Wall Solar Monitor

MicroPython firmware designed for a Raspberry Pi Pico 2 W to track the performance and thermal characteristics of a home solar panel array via MQTT and Home Assistant auto-discovery. This document serves as both a human-readable guide and a precise execution specification for GenAI software engineering agents.

## Overview

This project provides robust, headless environmental telemetry for a domestic solar installation. It polls four DS18B20 temperature probes on a single 1-wire bus, applies median filtering and delta thresholds, and publishes telemetry live to Home Assistant. To ensure long-term reliability for inaccessible hardware, it features a remote Over-The-Air (OTA) update architecture using the ugit library, complete with fallback protection.

## Architectural Decisions and Strict Constraints

* **No Local Logging (Strict Constraint):** Local file logging is entirely prohibited during standard execution to prevent unnecessary write wear on the microcontroller flash storage. Standard built-in `print()` statements are used exclusively for serial debugging. All diagnostics and telemetry are routed live via MQTT to Home Assistant.
* **Emergency Crash Logging:** Unhandled top-level exceptions are written to disk as `/fatal_crash.log`, transmitted upstream to Home Assistant via MQTT on the next clean boot, and then safely deleted to prevent flash wear.
* **Asynchronous Execution (Strict Constraint):** The firmware operates entirely within an asynchronous asyncio event loop. Blocking synchronous I/O operations are forbidden to prevent freezing the event loop, except during an active OTA download sequence.
* **OTA Validation and Rollback:** Firmware updates are executed seamlessly via MQTT. To protect the inaccessible hardware, an `ota_pending.flag` is created before downloading new code. The `boot.py` script acts as a gatekeeper; if the new `main.py` fails to initialise and clear the flag, `boot.py` deletes the corrupted file, restores `main_backup.py` and resets the hardware.
* **Resilient Network Management:** Employs an exponential backoff retry loop coupled with an eight-second hardware watchdog timer. If Wi-Fi or MQTT communication fails repeatedly, the system safely backs off before triggering a clean hardware reset.
* **Sensor Noise Reduction:** Implements a three-sample median filter combined with a 0.3°C delta threshold to eliminate raw sensor jitter and prevent excessive MQTT database chatter.
* **Fault Isolation:** If a single DS18B20 probe drops from the 1-wire bus, the logic flags only that specific sensor as offline while keeping the broader system status healthy, preventing transient bus jitter from cascading into a global system fault.
* **LED:** Blink the LED on, on activity only.

## Hardware Architecture and Wiring

* **Microcontroller:** Raspberry Pi Pico 2 W
* **Sensors:** Four DS18B20 temperature probes (designated Bottom, Middle, TopL, and TopR) sharing a single 1-wire bus on GPIO 15.
* **Pinout Connections:**
  * VCC (Red): 3V3 (Pin 36) - Power supply (3.3V)
  * GND (Black/Blue): GND (Pin 38) - System Ground
  * Data (Yellow/White): GP15 (Pin 20) - 1-Wire Data Line
* **One-Wire Pull-Up:** Incorporates two 4.7kΩ resistors in parallel on the 1-wire data line to ensure signal integrity and proper rising-edge performance across extended cable runs to the solar array.
* **DC Input Filtering:** Features a ferrite bead (ferrule) on the incoming 5V DC power rail to suppress high-frequency electrical noise and switching transients from nearby inverter equipment.

## Agent-Executable Runtime and Timing Specifications

* **Watchdog Timeout:** 8000 ms (eight seconds). The hardware watchdog must be fed on every iteration of the main loop.
* **Exponential Backoff Sequence:** Initial backoff is set to 1.0 second, scaling by a multiplier of two on each failure up to a maximum cap of 60.0 seconds.
* **Failure Threshold:** Reaching 20 consecutive failed connection attempts triggers an automatic hardware reset via `machine.reset()`.
* **Sensor Polling Cycle:** Non-blocking 750 ms 1-Wire conversion delay followed by active task coordination.

## Error Handling and Exception Paths

* **SensorReadError:** Raised when an individual 1-Wire sensor read fails or returns an 85.0°C power-on error state. Increments a failure counter; if failures reach three consecutive attempts, the specific sensor availability is published as offline.
* **Boot Exceptions:** SyntaxError, ImportError, and generic Exception types raised during the initial import of main.py are intercepted by boot.py to trigger fallback protections.
* **Exception Isolation:** Bare exception blocks are avoided where possible, ensuring socket errors, MQTT drops, and OS errors are caught and handled gracefully without tearing down a valid client state.

## Required Files for a New Installation

To set up the Wall Solar Monitor on a fresh device, ensure the following files and packages are placed on the Pico root:

* **`boot.py`**: Headless boot sequence watchdog, OTA validation, and rollback manager (v5.6.19).
* **`main.py`**: Core application logic, async loop, hardware drivers, and MQTT management (v5.6.19).
* **`secrets.py`**: Local operational credentials.
* **`ugit.py`**: Handles over-the-air firmware updates.
* **`umqtt.simple`**: Installed via Thonny's package manager for MQTT communication.

## Step-by-Step Installation Instructions

### Step 1: Install MicroPython Firmware
1. Download the official MicroPython UF2 firmware image for the **Raspberry Pi Pico 2 W**.
2. Hold down the **BOOTSEL** button on your Pico 2 W and plug it into your computer via USB. It will mount as a mass storage drive named `RPI-RP2`.
3. Drag and drop the downloaded `.uf2` file onto the `RPI-RP2` drive. The Pico will flash the firmware and reboot automatically.

### Step 2: Install Required Libraries via Thonny
1. Open Thonny and ensure your interpreter is set to **MicroPython (Raspberry Pi Pico)**.
2. Go to **Tools > Manage packages...**.
3. Search for `micropython-umqtt.simple` and install it directly to your device.

### Step 3: Create and Copy `secrets.py`
Create a file named `secrets.py` on your computer with your local network credentials and save it to the root of the Pico:

```python
wifiSsid = "YOUR_WIFI_SSID"
wifiPassword = "YOUR_WIFI_PASSWORD"
mqttBroker = "YOUR_HA_MQTT_IP_OR_HOST"
mqttUser = "mqtt_username"
mqttPassword = "mqtt_password"
```

### Step 4: Configure and Bootstrap `ugit.py`
1. Ensure `ugit.py` is saved in the root of your Pico.
2. Run the following setup commands in the Thonny REPL to link the device to your repository and generate the local configuration:

```python
import ugit
ugit.create_config(
    ssid="YOUR_WIFI_SSID",
    password="YOUR_WIFI_PASSWORD",
    user="gregcope",
    repository="pico-solar-monitor",
    ignore=["/README.md", "/secrets.py", "/secrets_example.py", "/config.json", "/main_backup.py", "/LICENSE", "/.gitignore"]
)
```

3. Execute the connection and initial sync command in the REPL to pull down your latest codebase (`boot.py` and `main.py`). The `time.sleep` loop prevents socket errors by ensuring the Wi-Fi is fully connected before fetching:

```python
import ugit
import network
import time

wlan = network.WLAN(network.STA_IF)
wlan.active(True)
wlan.connect("YOUR_WIFI_SSID", "YOUR_WIFI_PASSWORD")

while not wlan.isconnected():
    print("Waiting for Wi-Fi to connect...")
    time.sleep(1)

print("Wi-Fi Connected!")
ugit.pull_all(isconnected=True)
```

### Step 5: Final Verification and Boot
1. Press `Ctrl+D` in the Thonny REPL to perform a soft reset.
2. Confirm that the system initializes cleanly without any `ImportError` or missing module exceptions. You should see output similar to the following in the REPL console:

```text
MPY: soft reboot
boot.py v5.6.20: Starting boot sequence
boot.py v5.6.20: Environment initialised
```

Once bootstrapped, all future code changes pushed to your repository can be deployed directly by pressing the "Update Firmware" button within Home Assistant.

## Troubleshooting and Diagnostic Procedures

### 1. One-Wire Bus Errors
* **Symptom:** System status reports a bus fault or all sensors drop simultaneously.
* **Action:** Verify the parallel 4.7kΩ pull-up configuration between the 3.3V rail and the data line on GPIO 15. Check for loose terminal block screws or moisture ingress along the sensor cable run.

### 2. Single Sensor Offline or Reading 85.0°C
* **Symptom:** A specific probe displays 85.0°C or switches availability to offline.
* **Action:** An 85.0°C reading is the default power-on reset state of the DS18B20 chip, indicating a parasitic power drop or intermittent data line contact during conversion. Inspect the individual probe solder joints or crimp connectors.

### 3. MQTT Disconnection Loops
* **Symptom:** The Pico repeatedly resets or spends extended periods in the connecting state.
* **Action:** Check network signal strength via the rssi diagnostic entity. Confirm that the broker credentials stored in `secrets.py` are correct and that the MQTT keepalive grace period is respected.
